# Picture book plan (MarkBreak to Relay to print)

Make a picture book from manuscript to a print-accepted PDF: write in markbreak-app, lay out in Relay, place and frame illustrations, style the book with a custom style sheet, preflight, export interior and cover.

**Execution order for the writer (markbreak-app):** [PICTURE_BOOK_PHASES.md](PICTURE_BOOK_PHASES.md). This file stays the findings ledger. When a phase closes, mark its F/W/D items Landed here with commit ids.

**Writer phases 0–6 landed in tree** (docx import via mammoth, book sidebar, `book.css` preview lint, original image paths, Relay handoff / update). Tick the matching F/W items as you commit; dialect pin bump still needed after you push `markbreak.lua` role + `original:` image changes.

Relay keeps its own plan at `D:\repos\Relay\PICTURE_BOOK_PLAN.md` (Relay-side phases 0 to 8). This file is the cross-repo view: it covers the manuscript handoff, the style sheet, and the framing model, and section 10 maps every item here against Relay's plan so neither loses anything.

## 1. Definition of done

The acceptance book goes from source to vendor upload with no outside tool except a PDF/X validator:

- 32 interior pages, 250 x 250 mm trim (and a second run at 8.5 x 8.5 in), facing pages, self-ended.
- 14 double-page spreads with full-bleed art across the gutter, 2 single-page scenes, front and back matter.
- Text set over the art in frames, some on a translucent panel; text wrapping round a cut-out character on two scenes.
- One illustration in an ellipse frame, one with rounded corners, one cropped and panned inside its frame.
- All type and frame chrome driven by one `book.css` beside the manuscript, with a display face loaded through `@font-face`.
- Manuscript written in markbreak-app, one scene per `//break page`, opened in Relay, art placed by master placeholders.
- Author edits text after layout; Relay updates the story and every placed illustration stays where it was.
- Saved as `.rigz`, copied to another machine, reopened with zero missing links.
- Preflight is clean: no missing links or fonts, no image under 300 effective ppi, no overset, page count a multiple of 4, art reaches bleed on every outer edge.
- Interior PDF validates as PDF/X-4 (veraPDF) with an embedded output profile; a PDF/X-1a run validates when the CMYK path is on.
- Hardcover case cover with spine width computed from page count and paper, ISBN-13 barcode drawn from document data.
- The whole run is a CLI smoke (`--smoke-picture-book`) in Relay CI on Windows and Linux arm64.

Fixture art is generated by a script in-repo (no third-party illustrations; see `rigkit-git-safety`).

## 2. Rules this plan obeys

- **Contract first.** Every new field is named in RigWorks before a host POD exists. RigWorks `docs/idml.md` currently says *Out of scope for v1 - do not invent schemas for: graphic frames / placed images, groups, object styles, text wrap, anchored objects.* Phase 0 lifts that for the picture-book subset, explicitly, in RigWorks.
- **Data before code.** POD fields, then serializers, then compose / emit, then UI.
- **One function owns one behaviour.** Image fit maths is one pure function used by the reader and the PDF writer, so screen and paper cannot disagree.
- **Pi is the floor.** Print-resolution art is large; preview uses capped proxies, export uses originals. Parsers run at load / compose, never per frame.
- **Rebuilds stay cheap.** New weight goes into pack `.cpp` files; no CSS or ICC headers in hot core headers.
- **No fake stubs.** A UI control appears only when compose and PDF emit honour it. A field the writer cannot emit stays out of the POD.
- **Gates.** Format, contract smoke, the touched example, and Relay smokes pass before a phase is called done.

**W0.1 One image-fit schema** (F2)
- **Landed (draft):** RigWorks 1.6.0 (`7652aaa`, RigKit pointer `d4ed9d8`, both unpushed) adds [`rig.render.image_fit`](../RigKit/docs/contract/RigWorks/schemas/render/image-fit.md): `fit` = CSS `object-fit` literals (`fill` / `contain` / `cover` / `none` / `scale-down`, absent = `fill` = stretch), `positionX/Y` ratio plus `offsetX/Y` (= `object-position`), `scale`. Flips reuse `rig.render.sprite`; content rotation is out (bake it). The CSS round trip is [`docs/css.md`](../RigKit/docs/contract/RigWorks/docs/css.md); the IDML mapping covers `FrameFittingOption`. Relay 4.1 should consume this id instead of adding `rig.layout.image_fit`. A follow-up (`21f9f96`, RigKit `b30311f`) maps the rest of the CSS a picture book needs:
  - image `insets` (border plus padding) and `rig.layout.text_wrap` (draft) for `float` / `shape-outside`;
  - stroke `align`, plus fill, stroke and blend as the frame's border, background and opacity;
  - character `underline` / `strikethrough`, and paragraph `flowRole` variants for `[data-role=chapter]`;
  - table style selectors, and style lengths pinned to points.

  The table below is the original proposal.
- Home: RigWorks; lift "Graphic frames / placed images" out of `docs/idml.md` "Out of scope".
- Relay's plan proposes `rig.layout.image_fit` (`mode`, `scale`, `offsetX/Y`, `contentAlign`). Land **one** schema, extended with what picture books need here:

| Field | Type | Meaning |
|-------|------|---------|
| `mode` | enum | Literals per decision D11. Must cover: stretch (today's behaviour), contain, cover, native size |
| `scale` | float | Multiplier on the fitted size. Absent = 1 |
| `offsetX`, `offsetY` | float | Extra pan of content in page units. Absent = 0 |
| `contentAlign` | `rig.spatial.anchor` point literals | Where content sits before the offset. Absent = `center` |
| `rotation` | float | Content rotation in degrees, independent of the frame. Absent = 0 |
| `flipX`, `flipY` | bool | Mirror content. Absent = false |

- The frame shape clips its content: rectangle (with corner radius), ellipse, or path. An explicit `rig.paint.clip` on the drawable overrides the frame shape.
- "Fit frame to content" and "Center content" are operations, not stored state.
- Absent component must keep stretch, so existing `.rig` files do not change on upgrade (D11).
- Done when: RigWorks schema merged; vendored submodule bumped in RigKit.

### Phase 4 - Picture-book structure

**W4.1 Placeholder masters and scene flow** (F41, F43)
- A scene is the run of story blocks between page / odd / even breaks. Each scene takes the next spread or page, applies its master, and instantiates placeholders as real items with a back-reference (`scene`, `slot`). Scene text threads into text slots; scene images fill image slots with the slot's fit.
- Instantiated items are not `CLayoutBake`: they persist across re-compose, which refreshes their content but never moved geometry (`detached` flag).
- Complements Relay plan 4.6 / 5.4 (batch place by file name): placeholders are the manuscript-driven path, batch place the art-driven path. Both should exist.

**W4.2 Spread masters** - master pairs whose placeholders may span the spread.

**W4.3 Text wrap compose** (F6)
- `rigLayout` line breaker subtracts wrap obstacles per line; `bounds` and `jump` first, `shape` next. Verify the paragraph breaker takes per-line widths.

**W4.4 Art across the gutter** (F7)
- Same model as Relay plan 5.1 (parent to the verso, extend past trim, emit on the facing page clipped to its bleed box). Keep Relay's plan as the owner of this item.

**W4.5 Page-count tools** (F32)

**W4.6 Text over art**

## 7. Non-goals

- Inline / anchored images inside a text line (F13).
- Text wrap around an image's alpha contour.
- Drop shadows, glows, feathers, blend modes beyond opacity.
- A browser layout engine or HTML-first page CSS as the source of truth (MarkBreak specification non-goal). The sheet compiles to Rig styles.
- Vector transparency flattening for PDF/X-1a (refused with a listed reason, as Relay plan 6.3).
- IDML write-back of the new framing fields.

## 9. Risks

- **Pi:** W1.2 tessellated clips, W1.9 proxies, W2.5 LittleCMS, W3.1 parser. Each PR states arm64 build and measured frame time.
- **Rebuild cost:** `CLayout.h` additions stay POD-only; parser, ICC and preflight live in pack `.cpp` files.
- **Compatibility:** absent image-fit keeps stretch (D11); the house sheet compiles to today's metrics (W3.4); the `breakType` change ships a serializer migration test (W0.8).
- **Vendor specs move:** trims, spine formulas and bleed rules live in data files, checked against each vendor's current guide.
